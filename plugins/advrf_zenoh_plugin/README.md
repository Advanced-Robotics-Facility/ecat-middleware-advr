# ADVRF Zenoh plugin

This package connects the ADVRF shared-memory adapters to Zenoh using the
existing Protobuf schemas. It builds the reusable `advrf_zenoh_plugin` library
and installs the `zenoh_plugin` executable.

## Wire contract

All payloads use the binary Protobuf encoding generated by
`advrf_interfaces_protobuf`.

| Zenoh key | Protobuf payload |
|---|---|
| `rt/advrf/<robot>/joint_state` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/motor` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/valve` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/gripper` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/imu/<device>` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/power_board/<device>` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/pump/<device>` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/force_torque/<device>` | `iit.advrf.Ec_slave_pdo` |
| `rt/advrf/<robot>/cmd/joints` | `iit.advrf.Repl_cmd_vector` |
| `rq/advrf/<robot>/replCmd/request` query payload | `iit.advrf.Repl_cmd` |
| query response | `iit.advrf.Cmd_reply` |

Zenoh query responses use the queried request key, following Zenoh's native
query/reply model; a separate DDS-style reply topic is not required.

## Build and run

From the workspace root:

```bash
./scripts/select_middleware.sh zenoh
colcon build --metas colcon.nrt.meta --cmake-clean-cache
source install/setup.bash
zenoh_plugin
```

Use `zenoh_plugin --help` to display the adapter rate options. Zenoh endpoint
and routing behavior can be configured through the standard Zenoh environment
and configuration mechanisms.

The initial production implementation intentionally uses Protobuf rather than
CDR. A ROS 2-compatible CDR codec can be added independently without coupling
this transport to either DDS implementation.
